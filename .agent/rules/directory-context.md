# Directory Context Documentation Usage

When working on any file within a specific subdirectory of `src/`, you MUST prioritize reading the corresponding documentation file at `src/{directoryname}/AGENT.md`.

## Guidelines

1.  **Identify Context**: Before starting a task, identify which `src/` subdirectories are involved (e.g., `features`, `entities`, `shared`, `pages`).
2.  **Read Reference**: Immediately read the `AGENT.md` file for that directory (e.g., `src/features/AGENT.md`). These files contain a compressed representation of the entire directory's codebase and structure, generated by `repomix`.
3.  **Analyze Architecture & Style**: Before making any changes, analyze the architecture, logic flow, and code style patterns described in `AGENT.md`. You MUST ensure that your work is consistent with the existing patterns and follows the project's established conventions.
4.  **Prioritize Over Tree**: Use these files as your primary source of truth for the internal organization, logic, and relationships within that directory, rather than relying solely on file listings or partial reads.
5.  **Stay Updated**: Remember that these files are automatically updated by the CI/CD pipeline whenever a PR is merged into the base branch.

This approach ensures you have the full context of the module you are modifying, reducing context-switching and improving accuracy while maintaining high-quality, consistent code.
