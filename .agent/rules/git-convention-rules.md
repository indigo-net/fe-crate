# Git & PR Convention Rules

커밋 및 PR을 작성할 때 프로젝트의 Git 컨벤션을 엄격히 준수해야 합니다.

## 1. 커밋 메시지 규칙 (Commit Message Rules)

- **형식**: 반드시 `<type>: <설명> (<issue-id>)` 또는 `<type>: <설명>` 형식을 사용합니다.
- **주요 태그**: `feat`, `fix`, `chore`를 주로 사용합니다.
  - `feat`: 새로운 기능 구현
  - `fix`: 버그 수정
  - `chore`: 내부 작업, 규칙 수정, 설정 변경
- **언어**: 커밋 메시지의 상세 설명은 **반드시 한국어**로 작성합니다.
- **이슈 ID**: Jira 또는 GitHub 이슈 ID를 알고 있다면 반드시 포함합니다 (예: `(CRATE-123)`).

## 2. 풀 리퀘스트 규칙 (Pull Request Rules)

- **PR 제목**: `[ISSUE-ID] <설명>` 또는 `<type>: <설명>` 형식을 따르며, **반드시 한국어**로 작성합니다.
- **PR 템플릿**:
  - 반드시 `.github/PULL_REQUEST_TEMPLATE.md` 파일이 존재하는지 확인합니다.
  - 템플릿이 있다면 해당 형식을 기반으로 작성합니다.
  - 템플릿이 없다면 아래 구조를 사용하여 **한국어**로 매우 상세하게 작성합니다:
    - **개요 (Summary)**
    - **변경 사항 (Changes)**
    - **참고 사항 (Notes)**
- **주의 사항**: PR 본문은 다른 팀원이 내용을 명확히 이해할 수 있도록 **한국어**로 정성껏 작성해야 합니다.

## 3. 참고 문서

- 상세한 컨벤션 규칙은 `.docs/git-convention.md` 파일을 참고하십시오.
