# Git 컨벤션 가이드

## 커밋 메시지 형식 (Commit Message Format)

커밋 메시지는 다음 형식을 따릅니다:
`<type>: <설명> (<issue-id>)` 또는 `<type>: <설명>`

- **태그 (Types)**:
  - `feat`: 새로운 기능 추가 또는 주요 기능 변경
  - `fix`: 버그 수정
  - `chore`: 유지보수 작업, 의존성 업데이트, 내부 설정 변경
  - `docs`: 문서 수정 (소스 코드 변경 없음)
  - `style`: 코드 의미에 영향을 주지 않는 변경 (화이트스페이스, 포맷팅, 세미콜론 누락 등)
  - `refactor`: 버그 수정이나 기능 추가가 아닌 코드 구조 개선
  - `test`: 테스트 코드 추가 또는 수정

- **언어 규칙**:
  - **설명 부분은 반드시 한국어로 작성합니다.**

- **예시 (Examples)**:
  - `feat: 구글 로그인 기능 추가 (CRATE-123)`
  - `fix: 모바일 뷰에서 레이아웃 깨짐 현상 수정 (CRATE-456)`
  - `chore: tailwind v4 업데이트 및 관련 설정 변경`

## 풀 리퀘스트 컨벤션 (Pull Request Convention)

### PR 제목

`[ISSUE-ID] <설명>` 또는 `<type>: <설명>` 형식으로 작성하며, **한국어** 사용을 원칙으로 합니다.

- **예시**:
  - `[CRATE-123] 구글 로그인 기능 구현`
  - `feat: 구글 로그인 기능 구현 (CRATE-123)`

### PR 본문

PR 템플릿(`.github/PULL_REQUEST_TEMPLATE.md`)이 존재할 경우 해당 템플릿을 엄격히 따릅니다.
템플릿이 없는 경우, 다음 구조를 사용하여 **한국어**로 상세히 작성합니다.

1. **개요 (Summary)**: 해당 PR의 목적과 배경을 간략히 설명합니다.
2. **변경 사항 (Changes)**: 구현된 기능이나 변경된 로직을 상세히 나열합니다.
3. **참고 사항 (Notes)**: 리뷰어가 주의 깊게 봐야 할 부분이나 추가 정보.
4. **테스트 결과 (Test Results)**: 검증 완료 여부 및 결과 증빙 (스크린샷 등).
